# StudentHub + База даних (Supabase) — інструкція

Модель приватності: **кожен користувач бачить і синхронізує лише свої власні
дані**. Це працює на рівні бази даних (Row Level Security), тобто навіть якщо
десь у коді сайту буде помилка — сервер фізично не поверне чужий рядок.

Без входу застосунок продовжує працювати як зараз — локально, в одному
браузері. Після входу (пошта + магічне посилання, без паролів) дані
користувача підтягуються й зберігаються в базі — і доступні лише йому, з
будь-якого пристрою.

## 1. Створи проєкт Supabase
1. https://supabase.com → Sign up (безкоштовно) → New project.
2. Дочекайся створення проєкту (1-2 хв).

## 2. Створи таблицю й політики безпеки
1. У бічному меню: **SQL Editor → New query**.
2. Встав увесь вміст файлу `supabase-schema.sql` (поруч) → **Run**.
3. Перевір: **Table Editor → user_data** — таблиця має з'явитись, і на вкладці
   **RLS/Policies** мають бути 4 політики (select/insert/update/delete), усі
   з умовою `auth.uid() = owner`.

## 3. Візьми ключі доступу
1. **Project Settings → API**.
2. Скопіюй **Project URL** і **anon public key**.
   (anon key — публічний, його можна тримати відкрито в коді сайту: реальний
   захист дають RLS-політики з кроку 2, а не секретність ключа.)
3. Встав їх у `cloud-sync.js` замість:
   ```js
   const SUPABASE_URL = 'ВСТАВ_СЮДИ_URL_ПРОЕКТУ';
   const SUPABASE_ANON_KEY = 'ВСТАВ_СЮДИ_ANON_KEY';
   ```

## 4. Підключи власний SMTP (ОБОВ'ЯЗКОВО — інакше листи не дійдуть)
Вбудований поштовий сервіс Supabase **не призначений для реальних
користувачів**: без власного SMTP листи надсилаються лише на адреси, додані
як учасники (Team) твого проєкту в Supabase, — усім іншим (тобто всім
студентам) прийде помилка на кшталт `Error sending magic link email` або
`Email address not authorized`. Плюс ліміт — лише ~2 листи на годину на весь
проєкт. Це обмеження самого Supabase (безкоштовний план), не помилка коду.

Рішення — підключити безкоштовний SMTP через **Resend** (100 листів/день
безкоштовно, без картки):

1. Зареєструйся на https://resend.com (можна через Google/GitHub).
2. **API Keys → Create API Key** → назви як завгодно (напр. `studenthub`) →
   скопіюй ключ (показується один раз, починається з `re_...`).
   - Без своєї підтвердженої домени листи йтимуть з `onboarding@resend.dev` —
     цього достатньо для магічних посилань; свою домену можна підʼєднати
     пізніше в **Domains** на Resend, якщо захочеш красивішу адресу
     відправника.
3. У Supabase: **Authentication → Emails → SMTP Settings** (у деяких
   проєктах пункт лежить у **Authentication → Settings**) → увімкни
   **Enable Custom SMTP** і заповни:
   - **Sender email**: `onboarding@resend.dev` (або пошта з твоєї
     підтвердженої домени на Resend)
   - **Sender name**: `Student Hub`
   - **Host**: `smtp.resend.com`
   - **Port**: `465` (або `587`)
   - **Username**: `resend`
   - **Password**: твій API-ключ із кроку 2 (`re_...`)
   → **Save**.
4. **Authentication → Rate Limits** → онови ліміт на надсилання листів
   (напр. до 30–100 на годину) — старий ліміт «2/год» лишається чинним,
   поки не піднімеш його вручну.
5. Перевір: спробуй увійти на сайті зі звичайної пошти (не обовʼязково тієї,
   що зареєстрована в Supabase) — лист має прийти протягом хвилини
   (перевір і теку «Спам»).

## 5. (За бажанням) обмеж, хто може реєструватись
Якщо хочеш, щоб входити могли тільки студенти вашого закладу:
**Authentication → Settings → Allowed email domains** — вкажи, наприклад,
`@university.edu.ua`. Без цього кроку зареєструватися й отримати свій
приватний простір даних зможе будь-хто з поштою — це нормально й безпечно
для цієї моделі, оскільки кожен все одно бачить лише своє.

## 6. Онови сайт
Заміни файли на хостингу (GitHub Pages / Netlify / інше) на файли з цієї
папки — включно з новими `cloud-sync.js`, `supabase-schema.sql`, оновленим
`index.html`.

## 7. Перевір
1. Відкрий сайт → «☁️ Увійти / синхронізувати» → введи пошту.
2. Перейди за посиланням із листа.
3. Онови сторінку — кнопка має показати твою пошту замість «Увійти».
4. Додай/зміни щось у розкладі — за ~1с зміна піде в базу
   (**Table Editor → user_data** у Supabase — має з'явитись/оновитись рядок).
5. Відкрий сайт в іншому браузері/інкогніто, увійди тією ж поштою — маєш
   побачити ті самі дані. Увійди іншою поштою — має бути порожньо: чужих
   даних видно не буде.

## Обмеження цієї реалізації
- Без кроку 4 (власний SMTP) магічні посилання будуть приходити лише на
  пошти учасників проєкту в Supabase — усім іншим вхід не працюватиме.
- Спільного "розкладу групи, який бачать усі" в цій моделі більше немає —
  кожен імпортує Excel і веде дані сам. Якщо згодом захочеш поєднати:
  спільний розклад від старости + приватні особисті нотатки/дедлайни —
  це окрема, трохи складніша схема (дві таблиці замість однієї), скажи —
  зроблю.
